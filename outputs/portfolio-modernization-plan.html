Implementation handoff · 12 August 2026

The dual-version portfolio and one-click Sheet publishing path are implemented locally.

The canonical URLs now render a recruiter-focused v2, the classic portfolio is preserved under explicit /v1 routes, and a private Google Sheet can feed validated Vercel builds through a deliberate Apps Script menu action.

Repository: Next.js 16.3.0 App Router Default experience: v2 Modern Previous experience: v1 Classic Blog: deferred

Delivered locally

One application now contains two route trees, two isolated design systems, and one shared content contract.

The version control uses real links and preserves the visitor's current page. Google Sheets feeds the build rather than visitor requests. A database was deliberately excluded. External Google Cloud, Sheet, Apps Script, and Vercel credentials still require account-level setup.

01 · Decisions

What was built

These decisions are represented in the current source and were checked through lint, generated route types, TypeScript, a production build, dependency audit, and browser testing.

A

Modern owns the real URLs

/, /about, /projects, and /resume render v2. Existing external links continue to work and v2 remains the version search engines should index.

B

Classic is a visual archive

/v1, /v1/about, /v1/projects, and /v1/resume preserve the current glass-card design. The presentation is frozen, while shared factual content can remain current.

C

Google Sheet is the editor

Projects, profile copy, experience, education, and links come from a private Sheet. TypeScript schemas validate every publish. Images remain in the repository or an approved image host.

D

Publishing creates a deployment

A Sheet-bound Apps Script calls a secret Vercel Deploy Hook only when you explicitly publish. The build reads and validates the Sheet, then statically generates both versions.

02 · Version architecture

The toggle is navigation, not hidden application state

A real URL keeps direct sharing, browser history, accessibility, SEO, and static rendering predictable.

1

Visit /projects

The canonical v2 project page is served.

2

Select Classic

The control links to /v1/projects.

3

Render v1 shell

Classic fonts, CSS, navbar, cards, and footer load in isolation.

4

Browse inside v1

Classic navigation keeps the /v1 prefix.

5

Select Modern

The counterpart link returns to /projects.

Pushback: a cookie or localStorage selector sounds smoother, but it makes the selected version invisible in the URL and can cause dynamic rendering or a post-hydration visual flip. The full page load between isolated root layouts is acceptable and safer here.

05 · Google Sheets CMS

Publish builds, not live spreadsheet requests

The site changes infrequently and must remain reliable. Static generation gives a better failure boundary than querying Sheets for every request.

1

Edit private Sheet

Draft content remains editable without touching production.

2

Choose Publish

A bound Apps Script reads the explicit publish control.

3

Trigger deployment

UrlFetchApp sends a POST to the secret Vercel Deploy Hook.

4

Read and validate

The build uses a viewer-only service account and batch-reads required ranges.

5

Promote valid output

Both versions are regenerated. Invalid content fails the build and leaves the current site intact.

No database for phase one. Postgres would duplicate the Sheet, require synchronization and migrations, and introduce a write system that the portfolio does not need. Add a database only if content becomes multi-user, high-frequency, transactional, personalized, or needs a real review workflow.

06 · Sheet contract

Use typed tabs, stable IDs, and explicit ordering

A spreadsheet is not automatically a safe CMS. The build must reject missing IDs, invalid URLs, duplicate ranks, unknown statuses, and malformed lists.

TabPrimary columnsPurpose
Controlkey, valueStores schema version, content version, resume path, and request-only publish audit fields. Secrets never go in cells.
Profilekey, value, stateName, headline, biography, location, availability, and email.
Projectsid, slug, title, descriptions, status, year, technologies_csv, URLs, image_path, role, featured, sort_order, stateOne row per project with stable identifiers and deterministic order.
ProjectHighlightsid, project_id, sort_order, highlight, stateConcrete outcomes and implementation evidence without packing arrays into one cell.
Experienceid, organization, role, location, dates, summary, technologies_csv, sort_order, stateWork and meaningful project experience.
ExperienceHighlightsid, experience_id, highlight, sort_order, stateOrdered evidence tied to a published experience row.
Educationid, institution, credential, field, start_date, end_date, summary, sort_order, stateEducation timeline.
Linksid, type, label, url, sort_order, stateGitHub, LinkedIn, email, resume, and other reusable destinations.

Validation rules

  • Every record has a unique stable ID.
  • Ranks are finite integers and deterministic.
  • Content state is one of draft, published, or archived; project status is one of shipped, current, or earlier.
  • External links are valid HTTPS URLs.
  • Exactly one featured project is optional, never ambiguous.
  • Unknown columns warn; missing required columns fail.

Security rules

  • Sheet stays private and is shared read-only with a service account.
  • Service account key is stored only in Vercel environment variables.
  • Deploy Hook URL is stored in Apps Script Properties, never a cell.
  • Apps Script has the minimum external-request permission.
  • No client bundle receives Sheet IDs, keys, or API credentials.

08 · Acceptance gate

Definition of done

The work is complete only when these behaviors are verified in a production build, not merely inferred from source code.

Version behavior

  • Unprefixed routes load Modern by default.
  • Classic counterparts work on hard refresh and copied URLs.
  • The switch preserves home, about, projects, and resume context.
  • Modern and Classic render as separate root layouts.
  • Desktop and mobile layouts were visually inspected.

CMS code

  • Sheets credentials remain server-only.
  • All required ranges use one batch request.
  • Configured CMS errors fail the candidate build.
  • Apps Script records only requested status.
  • No automatic edit trigger or public CSV path exists.

Quality

  • Lint, TypeScript, and production build pass.
  • All eleven generated routes and metadata files are static.
  • Visible focus and reduced-motion styles are present.
  • A 390 pixel viewport has no page-level overflow.
  • Production dependency audit reports zero vulnerabilities.

Still requires your accounts

  • Create and populate the private Google Sheet.
  • Create the Google Cloud service account and key.
  • Create the Vercel Deploy Hook for the production branch.
  • Run one valid and one intentionally invalid real publish.
  • Confirm the final public site URL for canonical metadata.
